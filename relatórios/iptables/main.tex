\section{Introdução}

Neste projeto foi configurada a firewall da máquina \textit{SperServ} utilizando \texttt{iptables}, com o objetivo de proteger o servidor \textit{SpertaServer}.  

Foi adotada uma política de segurança restritiva, permitindo apenas as comunicações necessárias ao funcionamento do sistema. Neste relatório apresentam-se as principais regras implementadas, os métodos de teste utilizados e algumas evidências do funcionamento da firewall.

\section{Conteúdos}

\subsection{Default Policy Adotada}

Foi utilizada uma política \textit{deny by default}, bloqueando todo o tráfego não autorizado explicitamente.

\begin{itemize}
    \item \texttt{INPUT: DROP}
    \item \texttt{OUTPUT: DROP}
\end{itemize}

Esta abordagem reduz a superfície de ataque da máquina \textit{SperServ}, permitindo apenas os serviços necessários definidos nos requisitos do projeto.

\subsection{Regras Iptables Implementadas}

As principais regras implementadas foram:

\subsubsection{Permitir pings autorizados}

\begin{lstlisting}
sudo iptables -A INPUT -s 10.0.0.3 -p icmp -j ACCEPT
sudo iptables -A INPUT -s 10.0.3.2 -p icmp -j ACCEPT
sudo iptables -A INPUT -s 10.0.1.0/24 -p icmp -j ACCEPT
\end{lstlisting}

Estas regras permitem pedidos ICMP provenientes das máquinas administrativas e da sub-rede dos clientes.

\subsubsection{Permitir acesso ao SpertaServer}

\begin{lstlisting}
sudo iptables -A INPUT -p tcp -s 10.0.1.0/24 --dport 22345 -j ACCEPT
\end{lstlisting}

Permite ligações TCP ao \textit{SpertaServer} apenas a partir da sub-rede dos clientes.

\subsubsection{Permitir ligações SSH}

\begin{lstlisting}
sudo iptables -A INPUT -p tcp -s 10.0.2.4 --dport 22 -j ACCEPT
sudo iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 22 -j ACCEPT
\end{lstlisting}

Estas regras autorizam ligações SSH provenientes da máquina \textit{Broker} e da sub-rede local.

\subsubsection{Permitir comunicações internas}

\begin{lstlisting}
sudo iptables -A OUTPUT -o lo -j ACCEPT
\end{lstlisting}

Permite tráfego na interface \textit{loopback}.

\subsubsection{Permitir envio de pings com limite de 4 por segundo}

\begin{lstlisting}
sudo iptables -A OUTPUT -p icmp -d 10.0.0.0/24 \
-m limit --limit 4/second -j ACCEPT

sudo iptables -A OUTPUT -p icmp -d 10.0.0.0/24 -j DROP

sudo iptables -A OUTPUT -p icmp -d 10.0.2.4 -m limit --limit 4/second -j ACCEPT

sudo iptables -A OUTPUT -p icmp -d 10.0.2.4 -j DROP
\end{lstlisting}

A regra limita o envio de ICMP a 4 pacotes por segundo.

\subsubsection{Permitir conexão SSH para CondServ}

\begin{lstlisting}
sudo iptables -A OUTPUT -p tcp -d 10.0.3.3 --dport 22 -j ACCEPT
\end{lstlisting}

Permite ligações SSH da máquina \textit{SperServ} para \textit{CondServ}.

\subsubsection{Permitir tráfego ligações estabelecidas}

\begin{lstlisting}
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A OUTPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
\end{lstlisting}

Garantem o funcionamento correto de sessões já iniciadas, permitindo tráfego associado a ligações válidas.

\subsection{Métodos de Teste}

Foram realizados vários testes para validar as regras implementadas:

\begin{itemize}
    \item Testes de \texttt{ping} para verificar comunicações ICMP autorizadas;
    \item Testes da aplicação \textit{SpertaClient/SpertaServer};
    \item Ligações SSH entre máquinas autorizadas;
    \item Testes de limitação de tráfego ICMP.
\end{itemize}

Para os testes SSH foi utilizado:

\begin{lstlisting}
sudo /usr/sbin/sshd -D
ssh -X 10.0.0.2
\end{lstlisting}

Para validar o limite de ICMP:

\begin{lstlisting}
ping -i 0.1 10.0.0.3
\end{lstlisting}

\section{Observações e Dificuldades}

Durante o projeto surgiram dificuldades relacionadas com o terminal do \textit{webshell} do Mininet, devido a problemas de formatação dos comandos.

Além disso, a comunicação entre \textit{SpertaClient} e \textit{SpertaServer} foi configurada apenas para o porto \texttt{22345}, bloqueando ligações para outros portos.
